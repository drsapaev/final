# Queue service website refreshes during saves

**Date:** 2026-10-09 10:47
**Files:** `frontend/src/components/admin/ServiceCatalog.tsx`
**Severity:** medium

## Problem

A catalog refresh could start while the website-content PUT was still saving. Its response could contain the old database values and arrive after the PUT response, replacing the freshly saved editor state.

## Root Cause

The component serialized overlapping GET requests, but it did not coordinate refreshes with its save request. Refreshes can be started by the visible refresh button or by other catalog operations.

## Solution

Track the website-content save synchronously with a ref. Queue any refresh requested during the PUT and start a fresh GET after the PUT settles, so its response reflects the committed state. Ignore repeated save calls while one is in progress. Add debug-only `[FIX]` messages for queueing and replaying a refresh.

## Prevention

When reviewing forms with both save and refresh paths, account for request ordering across reads and writes. A regression scenario should resolve an older GET after a successful PUT and confirm the editor keeps the saved data.
