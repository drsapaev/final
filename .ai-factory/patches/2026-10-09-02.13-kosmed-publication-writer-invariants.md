# Preserve public-site writer invariants

**Severity:** Medium

**Tags:** public-site, publication, doctor-profile, service-batch, admin-form

## Problem

Several existing Clinic OS writers could invalidate or bypass public-site publication state: doctor deactivation and deletion were not serialized with publication updates, service batch updates accepted the legacy `is_active` alias without the publication guard seeing it, and a doctor could clear the shared profile name used by the public card. Separately, a catalog refresh could replace unsaved website content in the admin form.

## Root cause

Publication invariants were enforced at the dedicated website writer but not consistently at other writers of the same rows and display fields. The frontend also treated every selected-service object refresh as a user selection change.

## Resolution

Use the existing doctor row lock for update and soft deletion, normalize service activity aliases before applying batch guards, reject blank doctor display names before profile writes, and preserve dirty form state across same-service refreshes. Clear the form's dirty state and notices only when the selected service changes or the save completes.

## Prevention

Keep a writer inventory for shared publication fields. Apply the same row-level serialization to every writer that changes publication eligibility, normalize legacy input aliases before invariant checks, and distinguish data refresh from user selection in live forms. Future regression coverage should exercise publication/deactivation interleavings, both activity field spellings, doctor profile name validation, and draft preservation during refresh.
