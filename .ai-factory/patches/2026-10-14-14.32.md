# Show structured QueueProfile deletion refusals

**Date:** 2026-10-14 14:32 Asia/Tashkent
**Files:** `frontend/src/components/admin/QueueProfilesManager.tsx`; focused interaction tests.
**Severity:** low

## Problem

An Admin could receive `[object Object]` after a profile deletion was rejected with HTTP 409. The backend already explains when a profile is in use or its bindings changed during deletion.

## Root Cause

The delete handler assumed `detail` was a string and called `String(detail)`. The update handler in the same component already supported the existing structured error envelope. The URL suffix `specialists` can be a profile key in DELETE `/queues/profiles/{profile_key}`; it does not imply a specialists-list GET.

## Solution

Reuse the existing `apiErrorMessage` formatter for single-profile deletion. Preserve the backend delete guard and show its message. No automatic archive, delete retry, request change, or backend change is introduced. Existing error logging remains in place without additional payload logging.

## Prevention

Two regressions use key `specialists` and the canonical `profile_has_significant_links` and `profile_binding_changed` envelopes. They verify the visible message, retained row, enabled hide action, and absence of an implicit archive/reload. Both failed before the fix; all 44 focused interaction/CSV cases pass afterward. Do not infer a request method or a production refusal reason from a console URL/status alone. Bulk/CSV result handling remains T17.
