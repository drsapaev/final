# Fix lesson — T11 shared-tag QR availability and Department profile defaults

## Root causes

- A clinic-wide selector selected the first visible `QueueProfile` for a Doctor's tag. The existing admission guard already knew how to reject ambiguous or unavailable published candidates, but the selector and legacy specialist list did not preserve the full candidate set through that check.
- Department provisioning copied `Department.active` into `QueueProfile.is_active`. Under T11, profile activity is a manual setting and Department activity is resolved separately, so creating a Department while inactive accidentally created a permanent manual archive.

## Fix

- Route QR selector/admission decisions through the common visible-profile resolver with every published candidate, including inactive candidates, so selection, legacy listing and join fail closed consistently.
- Initialize a newly auto-created profile with manual `is_active=True`; the parent controls effective availability until activated.

## Regression coverage

- A shared `ecg` tag with one disabled parent and one active published sibling is omitted from clinic-wide selection and `/queue/available-specialists`, and direct join is refused.
- Creating a Department with `active=False` keeps its profile manually active; the profile is effectively unavailable until the Department is activated.

## Reusable lesson

When identity is resolved from a non-unique tag, keep the complete published candidate set until the canonical ambiguity/availability check has run. Derived parent state must not be written into a separate manual-intent field.
