# Краткая инструкция для администратора и регистратора

**Обновлено:** 2026-09-26 (срез RQ-28; каждый шаг сверен с интерфейсом на момент слияния)
**Для кого:** администратор клиники и регистратор
**Подробности для разработчиков:** [adding-a-new-specialty.md](developer-guides/adding-a-new-specialty.md)

Права: все шаги раздела «Настройка» выполняет **администратор**. Регистратор работает с записями, очередями и QR-страницей пациентов, но не меняет справочники и не выпускает постоянные адреса направлений.

---

## 1. Новый врач имеющейся специальности

**Кто:** администратор.

Шаги:

1. **Пользователи** → «Добавить пользователя»: логин, пароль, ФИО, роль **Doctor**, пользователь активен.
2. **Врачи** → найдите созданного врача → «Редактировать»:
   - **Специальность** — выберите ключ отделения из списка (список строится из справочника отделений, например `cardiology`);
   - **Кабинет** — номер кабинета;
   - **Активен** — включено.

Признак готовности: врач появляется в мастере записи регистратора при фильтре по его отделению и на QR-странице направления (если у направления включена видимость на QR и врач активен). Пациенты, записанные к этому врачу, попадают в его отдельную очередь дня.

Примечание: универсальная роль — `Doctor`. Отдельные роли-специализации (Cardiologist, Dentist и т.п.) существуют для специализированных панелей, но для обычной работы очереди достаточно роли `Doctor` + правильно выбранной специальности врача.

## 2. Новая специальность (новое направление)

**Кто:** администратор.

Шаги (Отделения → «Добавить отделение»):

1. **Название** (рус/узб), **Ключ** — только строчные латинские буквы, цифры и `_`, начинается с буквы, до 50 символов (например `neurology`); форма проверяет это сразу и показывает понятную ошибку.
2. При необходимости — **порядок сортировки**, иконка и цвет вкладки.
3. Сохраните. Система автоматически создаёт: вкладку регистратуры (профиль очереди с тегом = ключу), категорию услуг и услугу-консультацию по умолчанию.

⚠️ **Известное ограничение (до отдельной миграции).** Автоматический код услуги по умолчанию строится как `<ключ>_consult` и не помещается в лимит базы данных (10 символов). На PostgreSQL создание отделения с ключом длиннее ~2 символов без явного короткого кода услуги завершается ошибкой. Рабочий путь на сегодня: создать отделение через API с явным коротким кодом услуги (`integration.service_code`, не длиннее 10 символов, например `N01`) — это шаг для технического специалиста. Ограничение зарегистрировано в плане (backlog E-069, нужна миграция) и будет снято отдельным срезом.

Признак готовности: новая вкладка появляется у регистратора и на QR-странице; услуги с ключом отделения попадают в фильтр этой вкладки.

## 3. Услуга без врача (ресурсная очередь)

**Кто:** администратор (справочник), регистратор (запись).

Шаги:

1. **Услуги → Справочник услуг** → «Добавить услугу»: название, цена, отделение, тег очереди.
2. Выключите переключатель **«Требует врача»** (`requires_doctor`).

Что это даёт: запись на такую услугу не требует выбора врача — пациент встаёт в **ресурсную очередь направления** (владелец очереди — направление, а не врач; кабинет берётся из реестра направлений). Обслуживает такую очередь администратор/ресурс; врач из панели врача ресурсный талон обслужить не может (доступ запрещён по контракту QD-2C).

Признак готовности: в мастере записи услуга выбирается без списка врачей; на QR-странице направления пациент выбирает направление, а не врача.

Примечание: услуга-консультация, создаваемая автоматически вместе с отделением, тоже создаётся без привязки к врачу (`requires_doctor = false`) — если врач нужен, создайте/настройте услугу консультации вручную с включённым «Требует врача».

## 4. Несколько услуг за один визит (корзина)

**Кто:** регистратор.

Шаги: в мастере записи добавьте услуги в корзину по очереди (можно из разных категорий) → проверьте состав и итог → завершите запись. Итоговая сумма подтверждается **серверной котировкой**; если состав корзины перестал быть допустимым (услугу отключили/удалили), мастер не запишет «молча» — появится явная подсказка (добавить заново или обновить список услуг), а введённые данные пациента не теряются.

Кассир видит такую запись как один визит со всеми услугами и принимает оплату одним платежом (группировка аллокаций — на сервере).

Примечание: сохранённые **наборы-пресеты** услуг («пакеты») пока не реализованы (запланированы в RQ-25) — сейчас услуги добавляются в корзину по одной.

## 5. Вкладка-обзор, вкладки направлений и QR

**Кто:** регистратор (ежедневная работа), администратор (настройка видимости и постоянных адресов).

Экраны регистратуры сохраняют отдельное назначение (решение D-07):

- **Обзор (Welcome)** — стартовый экран: быстрые действия и группировка сегодняшних записей по врачам («Пациентов: N» — счётчик подписан единицей и скоупом: записи этого дня этого врача).
- **Записи (Worklist)** — рабочий список с фильтрами по вкладкам-направлениям; вкладка = профиль очереди (теги направляют услуги в нужную вкладку).
- **Онлайн-очередь (Queue)** — управление живой очередью и временными QR.

Два вида QR:

1. **Временный QR (на день/специалиста):** Онлайн-очередь → выберите специалиста → «Генерировать QR для выбранного специалиста» (или общий QR для всех специалистов). У кода есть срок действия — если он истёк, сгенерируйте новый; скачать/распечатать можно из того же окна.
2. **Постоянный адрес направления (`/q/<код>`):** **Администратор** → «Настройка направлений» (`/admin/setup-directions`) → выпустить постоянный адрес для направления. Адрес один и тот же навсегда (переименование направления его не меняет, повторный выпуск возвращает тот же код, после снятия с учёта и возврата адрес оживает тот же). Пациент открывает адрес, видит направление и выбирает врача/очередь.

Признаки готовности QR: направление видно на QR-странице только при включённой видимости на QR и активном профиле; скрытое/архивное направление не выдаёт талоны (анонимный отказ, без деталей). Список направлений, видимых пациенту, синхронизируется: новое/переименованное/отключённое направление у регистратора обновляется при возврате к сессии, по восстановлению сети, по кнопке обновления сеанса или после выпуска изменений администратором.

## 6. Перенос направлений между контурами (CSV)

**Кто:** администратор.

**Услуги → Вкладки регистратуры** → экспорт скачивает CSV со всеми полями профилей (ключи, названия, теги, видимость на QR); импорт проверяет файл до записи и показывает построчные результаты — частичный отказ не записывает строки молча. Дубли ключей и несуществующие отделения/теги отклоняются с объяснением.
