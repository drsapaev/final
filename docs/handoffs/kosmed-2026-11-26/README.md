## С чего начать

1. **Панель медсестры, #4300.** Блок новых назначений после закрытия талона уже в Draft. [Frontend CI](https://github.com/drsapaev/final/actions/runs/45742765383) и [повторная проверка оформления](https://github.com/drsapaev/final/actions/runs/45747212014) прошли. На точном SHA отдельный тест прошёл реальные FastAPI-маршруты с синтетическими пользователями и одноразовой PostgreSQL 16.2: медсестра вызывает, начинает и завершает первую услугу; врач через `PUT /api/v1/doctor/visits/{visit_id}/add-service?service_id=…` добавляет вторую услугу из каталога; ответ станции содержит её как ожидающую на том же закрытом талоне и в том же визите. Контрольная станция пустая, нового талона нет. Схема из метаданных ORM, не проверка миграций. [Архивированный сценарий](4300-asgi-acceptance.py) предназначен для отдельной тестовой копии, не для запуска на рабочей системе. Следующий шаг: реальный Chromium на изолированном API и БД без подмены запросов, по возможности с Alembic. После reload проверить видимый блок, отсутствие POST и отделение станций. Приёмку в браузере и выпуск пока не проводили. Создание нового талона регистратора на тот же Visit остаётся отдельным сценарием: не открывать старый талон, не создавать второй Visit или счёт. Обычный edit-delta не подходит, legacy batch не передаёт Visit, confirm меняет жизненный цикл.
2. **Единый вызов, #4274.** [Точная синтетическая облачная проверка](https://github.com/drsapaev/final/actions/runs/45649745126) прошла; GitHub ранее показал `unstable` из-за двух CodeQL-задач, остановившихся на публикации SARIF; подтверждённой новой находки нет. [Штатный прогон слияния](https://github.com/drsapaev/final/actions/runs/45654509544) остановился до merge, так как состояние было не `clean`. Не обходить защиту, не гонять пустые коммиты. [Локально проверенная правка](4274-manual-warning.patch) показывает врачу и кардиологу предупреждение о частичной/неподтверждённой доставке при успешной смене состояния; локально 34 теста, продуктовая ветка не изменена. Применять только после сверки с фактическим head. Незавершённая серверная идея: один зависший сокет не должен задерживать здоровые табло; на точной ветке повторить регрессию с ограничением времени на получателя, без повторной отправки при неоднозначном результате и без поломки подписки обновления приватности. Утверждённый код не подменён черновым патчем.
3. **Обследование, #4278.** В совместном локальном прогоне с #4274 возобновление использовало тот же Visit, но после смены даты клиники карточка терялась после перезагрузки, а при неактивной очереди прежний экран получал 409. Зафиксировать серверный способ найти начатый визит через границу суток отдельно от права возобновлять старую неактивную очередь. Сверить тот же Visit, ЭМК и права; не возвращать прошлые талоны в сегодняшнюю очередь.
4. **Табло, #4285.** Разработка параллельна, интеграция после проверки общего вызова #4274. [Отдельная тестовая ветка](https://github.com/drsapaev/final/tree/1698f8249ba7f54418a57d7c033260aebde42cdf) и [браузерный прогон](https://github.com/drsapaev/final/actions/runs/45659473781) покрывают поздние события и тихое восстановление через подменённые REST/WS; не переносить тестовый workflow как продукт. Дальше: серверно применять одну привязку холла/зоны/кабинета на снимок, оба вида обновлений и вызовы; пустая привязка не даёт широкого доступа. Использовать устойчивые Doctor/QueueResource ID, не DailyQueue ID. Отдельно подтвердить применённую версию конфигурации выбранным устройством (светлая → тёмная, второй экран без изменений, отключение и запоздавшие подтверждения). После этого проверить на двух телевизорах читаемость, полное русское/узбекское объявление с холодного старта, повторный вызов, одинаковые номера, смену кабинета и Wi‑Fi. Физическая приёмка не проведена.
5. **ЭМК #4236 и лаборатория #4251.** Оба Draft, пауза сохраняется. До общего теста сверить пересечения и единственный Alembic head после объединения с актуальным main. Для общего врача проверить один Start и открытие/сохранение/повторное открытие того же Visit. Пилот с двумя синтетическими неврологами: общая форма не должна заменять код `neurology` на `general` в сохранённой карте и истории её автора; не менять старые подписанные записи. Для лаборатории отдельно доказать правильную услугу и роль при заборе, повторном заборе, утверждении и показе исправленного результата в ЭМК; строить это отдельно от закрытия талона и визита.
