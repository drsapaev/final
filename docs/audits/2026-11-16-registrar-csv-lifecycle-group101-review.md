## NEW `REGCSV-FE-001` — P3 / SOURCE-CONFIRMED OPEN — Blob URL not released after repeated CSV exports

**Evidence:** [`frontend/src/pages/registrar/registrarCsv.ts:105–115`](https://github.com/drsapaev/final/blob/a8531540cfcd1039710a1362c979573820ba56b1/frontend/src/pages/registrar/registrarCsv.ts#L105-L115) creates a new Blob and **`URL.createObjectURL(blob)`** for each export, attaches a temporary anchor, calls `link.click()`, then removes the DOM element. **There is no `URL.revokeObjectURL(url)`** in that function and it does not return the URL to the caller for cleanup. Removing the anchor does not itself release the blob URL. In a long-lived clinic registrar tab, multiple exports can accumulate browser-held Blob URL allocations until document unload.

**Real callsites:** [`EnhancedAppointmentsTable.tsx:96–110`](https://github.com/drsapaev/final/blob/a8531540cfcd1039710a1362c979573820ba56b1/frontend/src/components/tables/EnhancedAppointmentsTable.tsx#L96-L110) invokes `downloadCSV(csvContent, filename)` from its toolbar; [`WelcomeView.tsx:449–456`](https://github.com/drsapaev/final/blob/a8531540cfcd1039710a1362c979573820ba56b1/frontend/src/pages/registrar/views/WelcomeView.tsx#L449-L456) does the same from the Welcome quick export. The filename/content scope problem in Welcome belongs to the **existing** `REGWELCOME-FE-002`; this finding concerns only **browser object URL resource ownership** common to both callsites, not the data selected.

**Impact/severity:** P3 resource cleanup / possible memory growth on repeated downloads in a long-running desktop tab. This is **not** evidence of production OOM, PHI exposure or server-side leak. File sizes and browser garbage collection vary; exact operational impact needs an isolated browser memory check.

**Synthetic fail-first acceptance:** isolate `downloadCSV` with fake `Blob`/object URL/anchor APIs; perform N sequential exports, assert one URL created per export and **every created URL eventually revoked** after the browser download has been initiated, including safe cleanup on thrown click where appropriate. Verify that `download` filename/BOM/content remain intact and that revoking immediately does **not** abort a real download on supported browsers (use a safe post-click cleanup strategy). Browser smoke: 20 repeated synthetic CSV exports in a long-lived tab, verify no sustained blob URL retention and downloads remain functional. No real patient data.

**Status:** `OPEN / SOURCE-CONFIRMED / BROWSER_REPRO_PENDING / NOT_FIXED`. Fixing agent owns any implementation.
