## 2. Root cause of successful-completion URL/tab split

[`CardiologistPanelUnified.tsx` on previous main](https://github.com/drsapaev/final/blob/d7eb9729248f949af5c74b45f1fdf26b914835fe/frontend/src/pages/CardiologistPanelUnified.tsx) called `setActiveTab('queue')` after confirmed `completeVisit`, but left URL `?tab=visit`. The same component also has an effect (based on `location.search, activeTab`) that restores `activeTab` from an explicit `tab` URL parameter. The shared [`useDoctorPanelState`](https://github.com/drsapaev/final/blob/d7eb9729248f949af5c74b45f1fdf26b914835fe/frontend/src/hooks/useDoctorPanelState.ts) uses canonical route navigation for ordinary tab changes, while this success path bypassed it. Outcome: confirmation of completed visit could leave an **empty visit screen**, rather than reliably returning to queue.

**New revision on same PR #4106** (head `eda4105130ec1553eefca1ee3ca9d99196b8afb8`): `CardiologistPanelUnified.tsx` now updates the **existing** `tab` query to `queue` with `useNavigate(..., {replace:true})` on the server-confirmed completion path and sets the tab to `queue`, preventing the URL-sync effect from reverting to the empty visit. It preserves the original direct successful-completion behavior and does not touch the shared dirty-draft navigation hook; this workflow's draft-guard semantics still require independent clinical review. The React test now includes a **RouteQueryProbe** that verifies `?tab=queue` for a positive completion and `?tab=visit` remains unchanged for stale A replies.

**Safety scope:** no new endpoint/queue command, no new auto-call in stale branches, no financial state mutation, no EMR API schema change, no clinical data from production. Test data synthetic. A stale successful A ACK after B selection is discarded as before; additionally stale rejected/ambiguous/network A continuations do not surface A's error or refresh from B. The shared `loading` cleanup remains unconditional to avoid B getting stuck busy after A settles. **A potential residual** is that a successful completion deep link might retain other URL keys such as `patientId` and `visitId`; those were not changed in this narrowly scoped patch and deserve separate review rather than claiming full route-context cleanup.
