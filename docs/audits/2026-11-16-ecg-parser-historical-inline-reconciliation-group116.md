## ECGPARSER-FE-002 — FIXED_VERIFIED_ON_MAIN

**Original P1:** `parseInt(null)` yielded NaN, but old unconditional normal branches classified absent/invalid heart rate and axis as *normal*; `parseInt('120bad')` accepted bad measurements. This can create clinical false reassurance.

- Current [`ECGParser.tsx`](https://github.com/drsapaev/final/blob/835eb01b6a664ef3485a6ce4e1590313ca937b75/frontend/src/components/cardiology/ECGParser.tsx#L19-L32) uses `toFiniteNumber`, requiring the entire string to match strict numeric syntax and finite values. [`analyzeECGParameters`](https://github.com/drsapaev/final/blob/835eb01b6a664ef3485a6ce4e1590313ca937b75/frontend/src/components/cardiology/ECGParser.tsx#L248-L322) explicitly emits `hr_not_measured` or `axis_not_measured` for absent/invalid input, allowing normal only with verified finite numbers. QRS axis is taken from `qrsAxis` rather than `pAxis` (separate later retro-fix).
- [Behavioral `ECGParser.contract.test.tsx`](https://github.com/drsapaev/final/blob/835eb01b6a664ef3485a6ce4e1590313ca937b75/frontend/src/components/cardiology/__tests__/ECGParser.contract.test.tsx#L183-L255) covers absent `null`, empty/malformed `120bad` inputs, valid HR 75/axis 0, tachy/brady boundaries, malformed PR, and XML upload with no HR/axis to assert explicit `not measured`, never normal. These are actual component/parser tests (not only source-text assertions).
- **Creditable [x]** based on current source + behavioral coverage + successful #3965 CI, not on PR title alone.

## ECGPARSER-FE-003 — FIXED_VERIFIED_ON_MAIN

- Current [`ECGViewer.tsx`](https://github.com/drsapaev/final/blob/835eb01b6a664ef3485a6ce4e1590313ca937b75/frontend/src/components/cardiology/ECGViewer.tsx#L460-L499) defines `firstFiniteNumber`, maps `qrs_duration` from `p.qrs_duration, p.qrsDuration, p.qrsInterval` and `qt_corrected` from `p.qt_corrected, p.qtCorrected, p.qtcInterval`, keeping `qt_interval` separate; missing values remain null, with P-wave axis never relabeled QRS.

Also tests QRS axis vs P axis. No live records.

## ECGPARSER-FE-001 — PARTIAL / REMAINS UNVERIFIED; NOT CREDITED

**Original P1 candidate:** any *syntactically valid* XML (including `<unrelated/>` or empty `<ClinicalDocument/>`) was treated as parsed ECG and could result in `source:'device'` persistence with no real data. The original audit explicitly required schema/identity **and units** validation, not merely XML validity.

- [`ECGParser.tsx`](https://github.com/drsapaev/final/blob/835eb01b6a664ef3485a6ce4e1590313ca937b75/frontend/src/components/cardiology/ECGParser.tsx#L79-L174) now rejects XML without any recognized measurement/rhythm/waveform, and [tests](https://github.com/drsapaev/final/blob/835eb01b6a664ef3485a6ce4e1590313ca937b75/frontend/src/components/cardiology/__tests__/ECGParser.contract.test.tsx#L129-L182) show `<unrelated/>`, empty `<ClinicalDocument/>` and free-text interpretation no longer produce a structured record. This is **real, useful partial remediation**.
- **Source-confirmed residual:** `parseXMLFile` calls `xmlDoc.querySelector('heartRate')` via `extractXMLValue`, reads its `value`, then accepts `parameters.heartRate !== null` as sufficient for `success:true`. The code does **not** require an HL7 aECG root/namespace/vendor schema, patient/record identity consistency, or verify `unit` for HR/intervals. Thus a well-formed but unrelated document containing `<heartRate value="75"/>` satisfies the positive check even if its parent root is not an ECG or values have the wrong unit. Its positive test explicitly accepts minimal `<ECG><heartRate value="75"/></ECG>` with no unit or patient identity. **This is a deterministic source-path risk, not a confirmed production event or a reviewer-run fail-first test.**
- **Disposal:** keep `ECGPARSER-FE-001` [ ] / `PARTIAL_SCHEMA_UNIT_VALIDATION_MISSING`. Next bounded implementation must choose the exact supported XML formats (HL7 aECG vs vendor subset) and identify acceptable root/namespace, units and identity, then add negative tests for unrelated XML with heartRate, malformed/foreign units, and valid supported-format positive controls. This is a **clinical contract decision**: no speculative backend changes or blanket rejection of real vendor files without owner agreement. Existing ECG upload can remain usable for supported formats while unsafe unknown content must fail closed; no live file test or patient data used here.
