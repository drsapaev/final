### QR-FE-008 — Queue-scoped WS refresh destroys multi-queue board read-model (P1)

**Code.** Backend [`display_websocket.py` L248–264](https://github.com/drsapaev/final/blob/106597d67ece48ee9380ded5725ba421aed8cbc0/backend/app/services/display_websocket.py#L248-L264) forms a `queue_entries` list for **one** `daily_queue.id`, broadcasts to **all connected boards** [L315–349](https://github.com/drsapaev/final/blob/106597d67ece48ee9380ded5725ba421aed8cbc0/backend/app/services/display_websocket.py#L315-L349). For every `event_type !== 'queue.created'`, [L598–607](https://github.com/drsapaev/final/blob/106597d67ece48ee9380ded5725ba421aed8cbc0/backend/app/services/display_websocket.py#L598-L607) sends this subset via `broadcast_daily_queue_state`. Frontend [`DisplayBoardUnified.tsx` L387–423](https://github.com/drsapaev/final/blob/106597d67ece48ee9380ded5725ba421aed8cbc0/frontend/src/pages/DisplayBoardUnified.tsx#L387-L423) calls `setQueueData(subset.map(...))` for such updates, thus **replacing the entire board**. On connection, however, [backend `display_websocket.py` L404–480](https://github.com/drsapaev/final/blob/106597d67ece48ee9380ded5725ba421aed8cbc0/backend/app/services/display_websocket.py#L404-L480) builds `initial_state` by iterating **all active queues** for the board. A multi-queue board showing A+B loses B after a `queue.updated` event for A, until a full snapshot arrives by reconnect/reload. Neither component nor event carries an explicit replace-global/replace-queue mode.

**Risk.** TV may incorrectly hide waiting patients in untouched departments and show only the most recently changed queue; canonical ticket/ordering database records remain unmodified. This is presentation read-model data loss, **not** queue fairness mutation. The current test [`DisplayBoardUnified.contract.test.tsx` L149–168](https://github.com/drsapaev/final/blob/106597d67ece48ee9380ded5725ba421aed8cbc0/frontend/src/pages/__tests__/DisplayBoardUnified.contract.test.tsx#L149-L168) sends only **one queue**; the same file's two-owner test uses initial_state only [L170–198](https://github.com/drsapaev/final/blob/106597d67ece48ee9380ded5725ba421aed8cbc0/frontend/src/pages/__tests__/DisplayBoardUnified.contract.test.tsx#L170-L198). Neither pins A+B → update A → B survives.

**Fail-first:** Render a board from `initial_state` with A#7 and B#7 (distinct IDs, owners, queue IDs). Push a real-format `queue_update` with `event_type='queue.updated'`, `data.queue_entries` only for A; assert B still visible, A updated, stable keys, no false cross-queue replacement. Check creation, cancellation, no-show and reconciliation across departments. Fix must define **backend-owned snapshot scope** (board-wide read or queue-scoped identity) before frontend merges; do not guess queue ownership by number or specialty label.

### QR-FE-012 — `queue.created` events appended without deduplication (P2 candidate)

**Code.** Backend [`display_websocket.py` L598–641](https://github.com/drsapaev/final/blob/106597d67ece48ee9380ded5725ba421aed8cbc0/backend/app/services/display_websocket.py#L598-L641) broadcasts `queue.created` as `queue_update` with `data.queue_entry_id,queue_id,number,...`.
