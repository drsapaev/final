# Bootstrap rule preservation map

This map records where each active safeguard remains after shortening
`AGENTS.md`. The bootstrap keeps the operational rule; linked files retain its
implementation detail and canonical ownership. Historical observations are
not promoted into current readiness claims.

| Rule group | Short rule retained in `AGENTS.md` | Canonical detail or owner |
|---|---|---|
| Task mode and execution gate | Classify the task; define anchors, paths, validation, and stop conditions. Use the required gate for risky work; retry a confirmed misroute once, then use only an authorized narrow override. | [Cyclic workflow](../runbooks/AGENT_CYCLIC_WORKFLOW.md), [Codex guard](../runbooks/CODEX_SUPERPOWERS_GUARD.md), `ai/langgraph/scripts/agent_gate.py` |
| PR cycle and repository state | Fresh `origin/main`, isolated branch/worktree, one purpose per PR, evidence and green checks before the next cycle; preserve unrelated changes. | [Cyclic workflow](../runbooks/AGENT_CYCLIC_WORKFLOW.md), [session worktrees](../runbooks/AGENT_SESSION_WORKTREES.md) |
| Production and staging boundary | Production changes run only from clean, synced main; staging is separate, synthetic-only, checked before use, and each Compose run is torn down unless a failure investigation is recorded in the task checkpoint. Never infer deployment health from CI or a smoke subset. | [Session worktrees](../runbooks/AGENT_SESSION_WORKTREES.md), [staging validation](../runbooks/STAGING_VALIDATION.md), `scripts/deploy_restart.ps1` |
| Pre-deploy claims | Do not say “it works”, “system verified”, or “deployment complete” until all required checks pass; report each result. | [Staging validation](../runbooks/STAGING_VALIDATION.md) |
