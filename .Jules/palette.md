## 2026-08-12 - Added aria-invalid to core form components
**Learning:** For custom macOS-style form wrappers (Checkbox, Input, Select, Textarea), the `error` boolean prop was visually highlighted (e.g., red borders) but not communicated to assistive technologies. It's crucial to map this visual error state to `aria-invalid={!!error}` on the underlying semantically actionable element (like the actual `<input>` or `role="checkbox"`) so screen readers can interpret form validation feedback.
**Action:** Always check that visual error/success states on custom form components are paired with appropriate ARIA attributes (`aria-invalid`, `aria-errormessage`) mapped directly to the target element receiving focus.
